Footnotes

1. Refresh methodology. Both feeds refresh the same way on request: the ingest re-scans each source for its newest files and rebuilds every metric from scratch — no manual re-entry and no stale carry-forward. The page is static between refreshes; there is no background job, timer, or scheduler. Asking to refresh the dashboard is what triggers a new pull.

2. Source detail. Source detail populates on the first ingest. Overlapping rolling windows are deduped on (Deal ID + Date) with the most recently delivered file winning; restated trailing-7-day files supersede earlier deliveries. All dates are handled in a single timezone (ET) before any join.

3. Metric basis. Every ratio is computed as summed numerator ÷ summed denominator — never an average of ratios. Cumulative KPI at day n is the range-to-date numerator ÷ the range-to-date denominator. Any metric that cannot be computed renders N/A, never 0.
